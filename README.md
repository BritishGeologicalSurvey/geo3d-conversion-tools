# ASC to G3D

Python code to convert ASCII GIS grid files to PGS Geo3D Viewer *.g3d file.

© UKRI (British Geological Survey) and the Polish Geological Institute 2026.


# Prerequisites

- Python
- Visual Studio Code

## BGS CLI Tool

### Development

Uses UV if you plan to develop the tool you will need UV installed an on the path.
- https://docs.astral.sh/uv/getting-started/installation/
- https://github.com/astral-sh/uv/releases

To install the dependencies with uv run:

```bash
uv sync --all-packages
```

There are a set of automated code tests written with pytest in `applications/asc-to-g3d/tests`. You can run them with:

```bash
uv run pytest -vv
```

Extensions
- python Visual Studio Code extension
- ruff Visual Studio Code extension
- pylance or pyright Visual Studio Code extension

### Executable

To build the executable:

`uv run pyinstaller --onefile --name asc-to-g3d applications/asc-to-g3d/src/asc_to_g3d/cli.py`

### Command Line Arguments

**Batch mode (directory of ASC files - to create a multiple G3D files):**

`> asc-to-g3d-<version>.exe batch -d <directory>`

Additional optional arguments.

These all have sensible defaults, you probably won't need them, but if you do:

- `--suffix-top T` suffix identifying 'top' files, default is "T"
- `--suffix-base B` suffix identifying 'base' files, default is "B"
- `--suffix-thick TH` suffix identifying 'thickness' files, default is "TH"
- `--suffix_out .g3d` suffix for output files, default is ".g3d"
- `-o <output directory>` output directory, defaults to source directory (-d)
- `-z <thickness>` set the value below which thickness is considered to be zero, the default is `1e-5`
- `-s` to turn on strict mode when comparing viable grid cells for numeric content, off by default.
- `-v` to turn on verbose mode, if you want to see what's happening behind the scenes or why something failed use this.
- `-c` optional configuration file that includes layer names, weights, colours, and groups.

Example command line for developers using UV (change para):

`uv run --package asc-to-g3d python -m asc_to_g3d.cli batch -v -d C:\Data\Projects\geo3d-viewer\Superficial_Deposits_Block_Model\ASCII_grids`   

**Single mode (specific set of ASC files - to create a single G3D file):**

`> asc-to-g3d-<version>.exe single -o <output-file> -top <file to top ASC file> -base <file to base ASC file> -thick <file to thickness ASC file>`  

You will need to provide at least 2 out of the 3 of: 

- `-top <file to top ASC file>`   
- `-base <file to base ASC file>`  
- `-thick <file to thickness ASC file>`  

Additional optional arguments.

These all have sensible defaults, you probably won't need them, but if you do:
 
- `-z <thickness>` set the value below which thickness is considered to be zero, the default is `1e-5`
- `-s` to turn on strict mode when comparing viable grid cells for numeric content, off by default.
- `-v` to turn on verbose mode, if you want to see what's happening behind the scenes or why something failed use this.
- `-c` optional configuration file that includes layer names, weights, colours, and groups.

Example command line developers using UV:

`uv run --package asc-to-g3d python -m asc_to_g3d.cli single -v -o .\data\output.g3d -top .\data\test_T.asc -base .\data\test_B.asc`

### Generating JSON

Originally the plan was to use the `datamodel-codegen` python library to convert JSON schema to pydantic classes. Unfortunately the schema didn't fully define all aspects of the `project.json` and the resultant classes couldn't be used to fully populate a `project.json` file. Hence, JSON is generated by bespoke code aligned to the current undrstanding of the `project.json` structure.
